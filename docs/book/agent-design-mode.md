# Agent设计模式

## 第一章
### GoF 23 种设计模式

GoF（Gang of Four，《设计模式：可复用面向对象软件的基础》四位作者）提出的 23 种经典设计模式，按目的分为三大类：**创建型**（对象怎么造）、**结构型**（对象怎么拼）、**行为型**（对象怎么协作）。

#### 创建型模式（Creational，5 种）

关注对象的创建过程，将「怎么创建」与「怎么使用」解耦。

| 设计模式 | 核心目的 | 工程视角的解释 | 类比 |
| --- | --- | --- | --- |
| 单例（Singleton） | 保证一个类全局只有一个实例，并提供统一访问点 | 用于全局配置、连接池、日志器等「天然只应存在一份」的资源，避免重复创建与状态不一致 | 一个国家只有一个中央银行，谁需要都找同一个 |
| 工厂方法（Factory Method） | 定义创建对象的接口，由子类决定实例化哪个类 | 新增产品类型时只加一个子类工厂，不改调用方代码，符合开闭原则 | 你点「一杯咖啡」，具体是拿铁还是美式由不同门店决定 |
| 抽象工厂（Abstract Factory） | 提供一组相关对象的创建接口，无需指定具体类 | 用于切换整套产品族（如换一套 UI 皮肤、换一种数据库驱动），保证族内组件互相搭配 | 买一整套「北欧风」家具，桌椅柜风格自动配套 |
| 建造者（Builder） | 将复杂对象的构建与表示分离，分步构造 | 参数极多或可选项复杂时，用链式调用逐步装配，避免超长构造函数 | 点汉堡时逐样选料：面包、肉、酱、配菜，最后组装出成品 |
| 原型（Prototype） | 通过克隆已有实例来创建新对象 | 创建成本高或需要保留当前状态时，复制现成对象比重新初始化更快 | 复印一份已填好的表格，再在副本上小改 |

#### 结构型模式（Structural，7 种）

关注类与对象的组合方式，用更灵活的结构应对变化。

| 设计模式 | 核心目的 | 工程视角的解释 | 类比 |
| --- | --- | --- | --- |
| 适配器（Adapter） | 把一个接口转换成客户端期望的另一个接口 | 让不兼容的旧代码 / 第三方库无需改动即可接入现有系统 | 电源转接头，把欧标插头插进国标插座 |
| 桥接（Bridge） | 将抽象与实现分离，使二者可独立变化 | 避免「维度爆炸」：如形状 × 颜色不写成 N×M 个类，而是两条继承线组合 | 遥控器（抽象）和电视（实现）各自演进，一个遥控器能配多台电视 |
| 组合（Composite） | 将对象组织成树形结构，统一处理单体与容器 | 让调用方对「叶子节点」和「组合节点」一视同仁，如文件与文件夹递归遍历 | 文件夹里可放文件也可放子文件夹，右键「计算大小」对两者都适用 |
| 装饰器（Decorator） | 动态地给对象叠加职责，替代继承扩展功能 | 用包裹的方式一层层加功能（如流加缓冲、加压缩），组合灵活且不改原类 | 咖啡上不断加料：加奶、加糖、加奶盖，每加一层还是杯咖啡 |
| 外观（Facade） | 为一组子系统提供统一的高层接口 | 隐藏内部复杂调用，对外暴露一个简单入口，降低耦合 | 前台一个电话搞定订房、叫车、送餐，你不用分别联系各部门 |
| 享元（Flyweight） | 通过共享细粒度对象来支持大量对象、节省内存 | 把可共享的「内部状态」抽出复用，如文字渲染中同一字符的字形只存一份 | 围棋只有黑白两种棋子，全盘共用两个「原型」，不为每颗棋子建对象 |
| 代理（Proxy） | 为对象提供一个替身以控制对它的访问 | 在真实对象前加一层，做懒加载、权限校验、缓存或远程调用 | 明星的经纪人：想找明星先过经纪人这关 |

#### 行为型模式（Behavioral，11 种）

关注对象之间的职责分配与通信方式。

| 设计模式 | 核心目的 | 工程视角的解释 | 类比 |
| --- | --- | --- | --- |
| 责任链（Chain of Responsibility） | 让多个对象依次处理请求，直到某个处理它 | 解耦发送者与接收者，如中间件 / 拦截器链，每一环决定处理或放行 | 请假审批逐级上报：组长处理不了转经理，经理不行转总监 |
| 命令（Command） | 将请求封装成对象，使其可参数化、排队、撤销 | 把「操作」变成一等公民，便于实现撤销/重做、事务、任务队列 | 餐厅点菜单：把「做一份宫保鸡丁」写成单子，可排队、可作废 |
| 解释器（Interpreter） | 为特定语言定义文法并解释其句子 | 用于实现小型 DSL / 规则表达式引擎，把语法规则映射成类 | 计算器把「1+2*3」按运算规则逐步解析求值 |
| 迭代器（Iterator） | 提供顺序访问聚合元素的方式而不暴露内部结构 | 统一集合的遍历接口，调用方无需关心底层是数组还是链表 | 电视遥控器的「下一个频道」，你不用知道频道内部怎么存的 |
| 中介者（Mediator） | 用一个中介对象封装一组对象间的交互 | 把网状的多对多依赖收敛成星形，对象只跟中介通信，降低耦合 | 机场塔台：飞机之间不直接对话，全部听塔台调度 |
| 备忘录（Memento） | 在不破坏封装的前提下捕获并恢复对象状态 | 实现存档 / 撤销功能，把某时刻的内部状态存下来供回滚 | 游戏存档：随时保存进度，失败后读档回到那一刻 |
| 观察者（Observer） | 定义一对多依赖，对象状态变化时自动通知依赖方 | 事件订阅/发布机制的基础，如数据变了自动刷新 UI | 订阅公众号：作者一发文，所有订阅者都收到推送 |
| 状态（State） | 让对象在内部状态改变时改变其行为 | 用状态对象替代大量 if/switch，如订单在不同状态下行为不同 | 红绿灯：同样是「到时间」，红灯变绿、绿灯变黄，行为由当前灯决定 |
| 策略（Strategy） | 定义一系列可互换的算法，使其独立于使用者 | 运行时切换算法（如不同排序、不同支付方式），避免硬编码分支 | 导航选路线：最快、最短、避拥堵，随时切换算法 |
| 模板方法（Template Method） | 在父类定义算法骨架，把某些步骤延迟到子类 | 固定整体流程，只让子类定制个别步骤，复用主干逻辑 | 冲泡饮料流程固定（烧水→冲泡→倒杯），泡茶还是泡咖啡只差「放什么」 |
| 访问者（Visitor） | 在不改变元素类的前提下为其定义新操作 | 把作用于对象结构的操作抽离出来，便于给稳定结构新增行为 | 体检医生（访问者）依次给每位员工做检查，员工无需改造自己 |

### MVC 示例

```java
// Model 数据与业务逻辑
class UserModel {
  private String name;
  private int age;

  public void updateProfile(String name, int age) {
    this.name = name;
    this.age = age;
    notifyObservers(); // 观察者模式的应用
  }
}

// View 展示层
class UserView {
  public void render(UserModel model) {
    System.out.println("name:" + model.getName());
    System.out.println("age:" + model.getAge());
  }
}

// Controller 控制层
class UserController {
  private UserModel model;
  private UserView view;
  private void handleUserInput(String name, int age) {
    model.updateProfile(name, age);
    view.render(model)
  }
}
```
