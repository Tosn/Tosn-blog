# vue3 响应式原理

A. vue3用Proxy替代了vue2的Oject.defineProperty，请描述Proxy 相比 defineProperty 到底解决了那些Vue2 时代的痛点?
Q. `Object.defineProperty` 只能**劫持对象已有的、你指定的那个属性**。它有两个致命局限:

- **新增/删除属性侦测不到**:`obj.newKey = 1` 或 `delete obj.key`,视图不更新。所以 Vue2 要提供 `Vue.set` / `Vue.delete` 打补丁。
- **数组的索引赋值和 length 变化侦测不到**:`arr[0] = x`、`arr.length = 0` 不触发更新。所以 Vue2 才去**重写那 7 个数组方法**(push/pop/shift/unshift/splice/sort/reverse)来手动通知。

而 `Proxy` 是**代理整个对象**,不是某个属性。它拦截的是"对这个对象的任意操作"(get/set/deleteProperty/has 等 13 种),所以:

- 新增、删除属性天然能侦测 → 不再需要 `Vue.set`;
- 数组索引、length 变化也能拦截 → 不用重写数组方法;
- 而且是**懒代理**:只有你访问到某个嵌套对象时才递归代理它,比 Vue2 初始化时递归遍历整个对象做 defineProperty **性能更好**(尤其大对象)。

一句话总结,面试可以这么收尾:**"defineProperty 劫持属性,Proxy 代理对象;前者管不了增删和数组,后者天生能管,还懒代理省性能。"**

A. ref 和 reactive 的区别是什么?为什么 ref 取值要 .value,而模板里又不用写 .value?
Q. 

|      | reactive            | ref                                            |
| ---- | ------------------- | ---------------------------------------------- |
| 用途 | 对象/数组           | 任意值(尤其**基本类型** number/string/boolean) |
| 取值 | 直接 `state.count`  | 要 `.value`                                    |
| 底层 | 直接 `Proxy` 包对象 | 包一层 `{ value }` 对象,再对这个对象做响应式   |

**为什么 ref 要 `.value`?** 因为 `Proxy` 只能代理**对象**,代理不了 `1`、`'abc'` 这种基本类型值。所以 Vue 把你的值塞进一个 `{ value: 你的值 }` 的对象里,再对这个包装对象做响应式追踪。你访问 `.value` 时触发 get 收集依赖,赋值 `.value` 时触发 set 派发更新。**`.value` 就是那层包装的入口。**

**为什么模板里不用写 `.value`?** 不是你说的"解构",而是 Vue 在编译模板时做了 **自动解包(unref / auto-unwrapping)**:模板编译器发现顶层是个 ref,渲染时自动帮你 `.value`。注意"顶层"两个字——如果 ref 嵌在 reactive 对象里,或者嵌在数组里,解包规则会有例外,但基础场景你记住"模板顶层 ref 自动解包"就够用。

**什么时候用哪个?** 经验法则:基本类型用 `ref`;一组相关的对象数据用 `reactive`;不确定就统一用 `ref`(团队里很多人为了心智一致全用 ref)。

A. 一个坑题:reactive 定义的对象,如果我直接解构 const { count } = state,count 还是响应式的吗?为什么?怎么解决?
Q. 

```js
const state = reactive({ count: 0 })
const { count } = state   // ❌ count 就是个普通的数字 0 了
```

**为什么丢了?** 响应式是靠 `Proxy` 挂在 `state` 这个**代理对象**上的——你必须"通过 state 去访问 count",那次 `get` 才会被拦截、才能收集依赖。而解构 `const { count } = state` 相当于**把 `state.count` 当时的值(0)拷贝给一个新的独立变量 count**,这个新变量和 `state` 的 Proxy 已经**没有任何关联**了,后续 `state.count` 再变,`count` 不会跟着变。基本类型是值拷贝,这层关系就断了。

**怎么解决?** 用 **`toRefs`**:å

```js
import { toRefs } from 'vue'
const state = reactive({ count: 0, name: 'zt' })
const { count, name } = toRefs(state)
// 现在 count 是个 ref,count.value 和 state.count 双向联动
console.log(count.value)  // 0
```

`toRefs` 把 reactive 对象的**每个属性都转成一个 ref**,而每个 ref 内部仍然指向原对象的对应属性(通过 getter/setter 转发),所以解构出来还是响应式的。**这也正好把 ②③ 串起来了**:ref 之所以能保住响应式,就是因为它是个"带 `.value` 的对象引用",引用不会因为解构而丢。

(补充:只取单个属性可以用 `toRef(state, 'count')`。)

# 工程化

A.  **Vite 为什么快?**
 你项目用的 Vite。请讲清楚:

- **开发环境**下,Vite 凭什么比 Webpack 启动快?核心机制是什么?
- 一个容易被忽略的点:Vite **生产环境打包**用的是什么?为什么开发和生产用两套东西,不觉得别扭吗?

Q. **核心机制:Vite 开发环境利用了浏览器原生的 ES Module(ESM)。**

- **Webpack(旧模式)**:启动时要先把**整个项目**的依赖图全部打包成 bundle,项目越大启动越慢——你改一行代码可能要等它重新构建一大坨。
- **Vite**:启动时**几乎不打包**。它直接起一个 dev server,把源码作为原生 ESM 丢给浏览器,**浏览器请求到哪个模块,Vite 才按需编译哪个模块**(比如把 `.vue`、`.ts` 现场转成浏览器能认的 JS 再返回)。所以启动是**秒级**的,和项目大小基本无关。
- 附加点:**依赖预构建**。第三方依赖(node_modules 里那些)Vite 会用 **esbuild**(Go 写的,比 JS 的构建工具快几十倍)提前打包一次并缓存,避免成百上千个小模块请求拖慢浏览器。

一句话:**"Vite 快在开发时不打包、按需编译,靠浏览器原生 ESM;依赖用 esbuild 预构建。"**

**Vite 生产打包用的是 Rollup。**

这正好回答你 (a) 的第二问。**为什么开发和生产用两套?**

- 开发环境追求**启动快、热更新快**,所以用"不打包 + esbuild"。
- 但生产环境如果也不打包,浏览器要发几百个模块请求,网络开销爆炸;而且要做 **tree-shaking、代码分割、压缩、兼容旧浏览器**——这些需要一个成熟的打包器。Vite 选了 **Rollup** 来做生产打包(Rollup 的产物质量和 tree-shaking 业界公认好)。

**"别扭吗?"** 这是 Vite 被诟病过的点——**开发和生产用两套引擎,理论上可能出现"开发跑得好、打包出问题"的不一致**(比如某些 esbuild 和 Rollup 行为差异)。这是 Vite 的一个已知 trade-off。(顺带一提,Vite 官方也在推进用 Rolldown——一个 Rust 写的、想统一开发和生产的新打包器——来解决这个割裂,你知道这个方向会是加分项。)

A. **一道具体的:路由懒加载**

- Vue Router 里路由懒加载怎么写?底层是靠什么实现按需加载的?
- 懒加载一定更好吗?有没有"反而变慢"或者需要注意的场景?

Q.  **写法你答对了**:`component: () => import('@/views/xxx.vue')`,正确。

**底层靠什么(你说不清楚)**:靠 **构建工具对动态 `import()` 的代码分割(code splitting)**。当 Webpack/Vite 看到 `import()` 这种**动态导入语法**,会把这个模块**单独拆成一个 chunk 文件**,不打进主包。运行时真正执行到这行 `() => import(...)` 才会去**发请求加载那个 chunk**。所以本质是:**动态 import 语法 → 构建工具切 chunk → 运行时按需加载**。这三段能串起来就够了。

**(c) 后半"不一定更好"你答对了,而且例子举得对** —— 小页面懒加载会带来"点进去才加载 → 多一次网络往返 → 短暂白屏/延迟",得不偿失。**补充一个更实战的点**:对于用户**大概率会访问的下一个页面**(比如登录后必进的首页),可以用 **`prefetch`** 提前偷偷加载,兼顾"不拖累首屏"和"进页面不卡"。这个"懒加载 + prefetch 组合拳"讲出来,面试官会觉得你真在生产上调过。
